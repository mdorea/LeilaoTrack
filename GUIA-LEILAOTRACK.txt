O QUE NUNCA FAZER

  no segredo SUPABASE_SERVICE_KEY do GitHub (passo 4).
- A chave PÚBLICA (anon ou publishable) pode ficar no site: quem

PASSO 4 · COLOCAR AS CHAVES NO GITHUB (5 min)
---------------------------------------------------------------------
1. No Supabase: engrenagem "Project Settings" > "API Keys"
   (ou "Data API" / "API").
   Você vai precisar de 3 coisas:
   a) Project URL: algo como https://abcdefghijkl.supabase.co
      (aparece em "Data API" ou no topo da página de API)
   b) Chave PÚBLICA: "Publishable key" (sb_publishable_...)
      ou, na aba "Legacy API keys", a "anon public".
   c) Chave SECRETA: "Secret key" (sb_secret_...)
      ou, na aba "Legacy API keys", a "service_role" (toque em Reveal).

2. No GitHub: https://github.com/mdorea/LeilaoTrack
   > Settings > Secrets and variables > Actions > "New repository secret"
   Crie estes 3 segredos (nome exatamente assim):

     SUPABASE_URL           =  o Project URL (a)
     SUPABASE_ANON_KEY      =  a chave PÚBLICA (b)
     SUPABASE_SERVICE_KEY   =  a chave SECRETA (c)

   Se por engano você colocar a chave secreta no SUPABASE_ANON_KEY,
   a publicação para com erro de propósito, para ela não vazar.

2. Escreva o NOME (aparece no "Bom dia, João") e o E-MAIL.
3. Toque em "Gerar convite". Aparece o código e 3 botões:

O que você, como administrador, NÃO vê: chaves de IA, perícias,
favoritos e cálculos das outras pessoas. Cada um vê só o seu.

SEGURANÇA: O QUE FOI FEITO
---------------------------------------------------------------------
- Acesso só por convite: sem código válido (12 letras/números,
  ~60 bits de acaso, guardado só como "hash"), o banco recusa criar
  a conta. 5 tentativas erradas bloqueiam o convite.
- Regras do banco (RLS) em todas as tabelas: cada pessoa só lê e
  grava o que é dela. Funções de administrador conferem o papel no
  próprio banco a cada chamada; esconder o botão não é a proteção.
- Os lotes ficam num arquivo privado: sem login de membro, nada.
- Senhas guardadas pelo Supabase com bcrypt; mínimo de 8 caracteres;
  senhas fáceis (12345678, sequências) são recusadas.
- Trocar a senha por código encerra as sessões em outros aparelhos.
- O site não carrega nenhum código de terceiros: as bibliotecas ficam
  hospedadas no próprio site, e uma política de segurança (CSP)
  proíbe scripts de fora, "eval" e envio de dados para endereços que
  não sejam o Supabase, a Anthropic ou o Google.
- Tudo que vem dos sites de leilão e da IA é tratado como texto: não
  vira código. O relatório da IA passa por um filtro (DOMPurify) que
  tira imagens, scripts e links perigosos (proteção contra documentos
  "envenenados" que tentam enganar a IA).
- Chave de IA: guardada na conta cifrada com a senha da própria pessoa
  (PBKDF2 + AES-GCM), então o banco só vê texto embaralhado; no
  aparelho, cifrada com uma chave que o navegador não deixa exportar;
  vai direto para a Anthropic/Google.
- CPF, CNPJ, telefones e e-mails dos documentos são ocultados antes
  de ir para a IA.
- O site não pode ser aberto dentro de outra página (anti-clickjacking)
  e não aparece em buscadores.
- A chave secreta do banco só existe nos segredos do GitHub; a
  publicação se recusa a colocá-la no site.
- O site só aceita conversar com o SEU projeto do Supabase (não com
  qualquer outro), mesmo que alguém consiga injetar código.
- O arquivo dos lotes ganha um nome novo e aleatório a cada leitura:
  se alguém removido do grupo tiver guardado um link do arquivo, ele
  para de receber lotes novos.
- As ferramentas do GitHub usadas na publicação estão travadas numa
  versão exata (não mudam sozinhas).
- Alertas do Telegram tratam o texto dos sites como texto puro.
- Links que a IA colocar no relatório mostram para onde levam.

Um ponto que depende do endereço: o site fica em mdorea.github.io,
que é o mesmo "endereço-base" de qualquer outro site que você publicar
pelo GitHub Pages nessa conta (ex.: repositórios do restaurante).
Por isso: não publique outros sites pelo GitHub Pages nessa conta, ou,
no futuro, use um domínio próprio só para o LeilãoTrack (cerca de
R$ 40 por ano), que separa tudo de vez.

Nenhum sistema é 100% inviolável. O que dá para garantir é que não há
porta aberta conhecida e que, se alguém descobrir a senha de um
membro, só vê os dados daquele membro. Boas práticas que ajudam:
- use senha forte no Supabase, no GitHub e no seu e-mail, com
  verificação em duas etapas (2FA) nos três;
- remova do grupo quem não usa mais;
- me peça uma revisão sempre que mudar algo importante.

SE ALGO DER ERRADO
---------------------------------------------------------------------
- Site mostra "Site em configuração": faltam os segredos SUPABASE_URL
  ou SUPABASE_ANON_KEY no GitHub, ou a publicação ainda não rodou
  depois de criá-los (passo 5).
- "Os lotes ainda não foram publicados": rode o passo 5 de novo e
  confira a pasta "privado" no Storage.
- "Convite ou código inválido": confira e-mail e código; gere um
  novo no painel se precisar.
- "Sua conta não está ativa neste grupo": a pessoa foi removida.
- Supabase grátis "pausa" projetos parados por 7 dias. A leitura de
  2 em 2 horas mantém o projeto ativo; se mesmo assim pausar, entre
  no painel do Supabase e toque em "Restore".
